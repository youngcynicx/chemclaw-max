# ChemClaw 统一前端：设计依据与交互验收

日期：2026-10-15。用途：约束本轮前端的视觉、信息结构与可验证交互。本文中的设计建议不是后端能力已交付的证明，也不代表作品已获奖。

## 1. 本轮设计结论

把 ChemClaw 做成一张可工作的研究台：从今天的待办进入，沿样品与实验事件找到证据，核对有歧义的字段，查库存与 Agent 的处理进度。聊天是快捷入口，证据和正式事实仍有稳定的页面与地址。

视觉使用纸白、墨绿和少量酸橙色。用精确排版、明确层级、连续状态与细节反馈体现品质。首页有一个与真实对象对应、可以点击的关系视图；进入工作流程后，让位于原页、表格与时间线。日常用户无需看懂内部能力名称或运行令牌。

“获奖级”在本项目里应转化为可以验收的标准：有辨识度的视觉语言、完成度高的交互、移动与键盘可用、真实且清楚的数据状态、快速反馈、稳定页面。不能以获奖案例的视觉复杂程度代替实验室工作效率。

## 3. 统一信息结构

侧栏只保留日常工作对象。Agent 名字出现在负责人与处理记录里，不让研究者先理解 Agent 架构才能操作。

| 一级入口 | 首屏应回答的问题 | 核心内容 |
| --- | --- | --- |
| 研究台 | 今天先处理什么？ | 待核对记录、最近样品、处理中的任务、需要补货的条目；一个可操作的样品关系视图。 |
| 共享知识 | 某个样品做过什么，依据在哪？ | 样品列表、事件时间线、带引用搜索、事件发生时间与系统获知时间、修订记录。 |
| 证据与核对 | 这页记录写了什么，哪些还不确定？ | 原件/预览与转写并排；字段—原页定位；集中澄清；草稿到正式记录的状态。 |
| 库存 | 有多少，最近为什么变了？ | 物料检索、数量与单位、位置、阈值、交易记录、相关实验与待处理调整。 |
| 协作任务 | 谁正在处理，卡在哪一步？ | 人类待答、Agent 运行、业务应用、送达状态；失败原因、允许的恢复动作。 |
| 连接与设置 | 当前在使用哪组数据？ | 明确的演示/连接标志、Core 连接与项目、能力范围、数据处理方式。 |

资源预约与里程碑可以在后续加入；本轮若没有形成可用界面，不放一个能点击却没有工作内容的一级入口。统一聊天面板从各页面唤起，并携带当前项目/样品上下文。聊天回答中的引用可进入同一套证据详情。

全局上下文按“工作区 / 项目 / 当前对象”展开。切换项目后清除上一个项目的搜索结果和打开对象；受限内容显示通用权限状态，不能先显示正文再弹错误。

## 4. 页面与视觉规格

### 4.1 桌面布局

- 侧栏约 216–236 px，顶部栏约 72–80 px；内容区以清晰网格布局，不铺满等权重圆角卡片。
- 页面上方使用小英文栏目名、中文主标题和一句帮助判断的说明；标题约 32–42 px，正文 14–16 px，表格 13–14 px。中文行高约 1.6，数字与单位保持同组。
- 主操作每个上下文只保留一个强强调按钮。次操作用细边框或文本按钮。需要核对的数量与来源缺口比无意义的增长百分比更有价值。
- 首页以 60/40 或 7/5 的非对称区块组织“当前研究对象”与“待核对”，下方使用横向列表与最近活动。关系视图应可直接进入对象，不能成为占半屏却不提供行动的装饰。
- 证据核对用约 55/45 的原页与字段区域，并保留稳定的顶部页码/版本。滚动字段区时原页保持可见；缩小屏幕后允许明确切换“原页 / 转写 / 字段”。

### 4.2 基础色与样式

| 用途 | 建议值 | 约束 |
| --- | --- | --- |
| 画布 | `#F4F5EF` | 低饱和纸白，不使用大面积彩色渐变。 |
| 内容表面 | `#FDFEF9` / `#FFFFFF` | 靠留白与细线分层，减少重阴影。 |
| 主文字 / 深色侧栏 | `#182922` | 长文有足够对比；反白文字不降到过低透明度。 |
| 次文字 | `#64716A` | 不用于关键状态或小字号下的唯一信息。 |
| 品牌重点 | `#D5F86B` | 只用于当前焦点与主操作；浅色背景配深墨文字。 |
| 细线 | `#DCE1D7` | 表格与分组共用，避免密集交叉网格。 |
| 待核对 | 低饱和琥珀底与深褐字 | 同时带文字，不依赖颜色识别。 |
| 异常 / 拒绝 | 克制的朱红 | 不把所有未完成状态都画成错误。 |

图标使用同一笔画系统。徽标应表达样品、来源连接或协作关系；避免把抽象连接图误画成真实化学结构并赋予科学含义。科学上无依据的动画不进入实验图表。

### 4.3 动效

界面响应 120–180 ms，抽屉/面板过渡约 200–280 ms。字段选中时，字段高亮与原页区域高亮同时变化。列表筛选保持上下文，必要时用轻微淡入帮助发现变化。

首页关系图可有低频运动，但指针移入、节点选择、打开详情时稳定下来。支持 `prefers-reduced-motion`，不强制入场动画、声音、自动摄像机移动或滚动劫持。动效不能遮盖错误或拖延按钮可用时间。

## 5. 与现有架构保持一致的交互

本节依据现有实施计划、S10 审阅与修复指南，特别是 R03、R05–R07、R11–R12。前端不能用状态文案弥补后端缺口。

1. **演示与真实连接是两种明确模式。** 演示使用合成数据，写入式操作只改变本地状态；页面常驻标识。真实连接仅使用已允许的 Core 接口。连接失败不能静默回退成“看起来仍是实时”的演示数据。
2. **本轮先提供诚实的只读连接。** S10 存在已复现的授权、批准、幂等与来源问题；没有证据证明修复完成前，真实写入不能因界面按钮漂亮而默认开启。前端隐藏按钮不是授权机制。
3. **上传与识别分开反馈。** 选中文件不等于原件已保存；原件保存不等于识别成功。没有真实识别器时显示“待转写 / 可人工录入”，不定时生成假识别结果。
4. **来源必须精确。** 字段旁有来源页、区域与版本；点击后看到相应原页。后端只提供 `artifact_id` 而没有受控下载/预览接口时，显示“预览暂不可用”，不拿演示图替代真实原件。
5. **不确定与错误分开。** 未读清的量值保留 unknown；解释与计算有独立标识。单纯转录配方不显示“已扣库存”。
6. **批准前展示准确变化。** 对象、提案版本、数量单位、前后值、证据和批准范围在同一上下文。主体由后端认证得出，不能由用户填写确认者名字替代。
7. **任务、业务、送达各自有状态。** 例如“整理完成 / 记录已保存 / 库存待处理”，而不是一个模糊的绿勾。“送达待确认”不能自动重跑业务。
8. **同源知识与时间。** 样品时间线与问答引用相同事件与 revision；历史快照以系统获知时间定义时，不能显示后来才保存的正式事实。
9. **凭据不进入静态包。** 本地连接凭据只在明确的本地桥接会话里使用，不持久化到公开资源、演示导出或源代码。静态托管预览不尝试读取用户本机文件。

## 6. 应优先做成的完整交互

### A. 从待核对到来源

点击“需核对” → 打开对应纸页 → 选中不清楚的量值 → 原页定位 → 编辑或保留未知 → 预览变化 → 明确提交结果。演示模式所有步骤标记为本地模拟；真实模式按 Core 能力显示允许动作。

### B. 从样品到可引用答案

检索样品 → 查看事件时间线 → 打开一条观察或测量 → 跳转来源 → 返回原滚动位置。搜索没有结果时给出清楚空状态，不能换成任意推荐答案。固定演示回答也应标记示例，并真正链接到展示的对应事实。

### C. 从库存到实验缘由

按名称/位置筛选 → 打开库存条目 → 查最近交易 → 打开关联实验。数量与单位总是同行，异维度数据不绘成可相加总量。阈值缺失时显示“未设置”，不默认为零或正常。

### D. 从任务到恢复行动

筛选待人答/运行中/异常 → 打开任务详情 → 看当前阶段、已完成结果与卡点 → 执行允许的回复或恢复。一次通知被关闭不等于业务状态变化。展示“重试”时说明重试的是读取、识别、业务步骤还是送达。

### E. 快捷入口

`Ctrl/Cmd + K` 打开全局搜索；输入后可筛选并用键盘选择，`Esc` 返回。全局上传入口支持选择与拖放、格式/大小反馈、取消和移除。抽屉关掉后焦点回到触发按钮。

## 7. 交付验收清单

- [ ] 1440 px 桌面、1024 px 窄桌面与约 390 px 手机宽度均无页面级横向溢出；表格可局部滚动。
- [ ] 所有一级导航、首页对象节点、条目和主按钮有实际工作内容；没有仅改变背景颜色的假交互。
- [ ] 至少完成“搜索 → 样品 → 事件 → 来源”与“待核对 → 字段定位 → 本地修订”两条可操作链路。
- [ ] 上传对 PNG/JPEG/PDF 与不支持文件分别反馈；不会把保存或选择成功误说成 OCR 成功。
- [ ] 演示数据、真实连接、加载、失败、空结果、无权限、缺预览有不同且清楚的页面状态。
- [ ] 真实连接失败后不混入演示数据；断开连接不保留真实正文在当前视图中。
- [ ] 表格、正文、徽章、按钮与焦点可见；状态同时有文字；仅键盘能完成导航、检索、打开/关闭对话框。
- [ ] 窗口/抽屉支持 `Esc`、焦点约束和关闭后焦点恢复；响应减少动效设置。
- [ ] 浏览器刷新后演示变更可按产品设计保留或明确重置；“重置演示”动作有真实效果。凭据不因此持久化。
- [ ] 量值保留单位；unknown、计划、报告记录、计算结果和正式事实在界面中区分。
- [ ] 浏览器控制台没有未处理错误，关键页面截图实际检查；本地与托管静态预览均可打开。
- [ ] README 清楚记录启动、演示边界、Core 只读连接、未接入能力；不宣称真实 OCR、真实平台或后端修复已完成。

## 8. 本轮审阅后的优先级

先做对象之间的连通性与证据核对，再精修动效。首页最大的视觉元素必须能解释“记录如何变成知识”；详情页最大的区域必须留给实际原件和可核对字段。

统一前端不要求把所有现有 capability 都做成按钮。真正统一的是同一个项目上下文、同一套对象身份、来源与状态语义，以及跨页面可回到原处的连续操作。
