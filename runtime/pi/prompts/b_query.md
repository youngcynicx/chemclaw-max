比较或汇总前逐项核对 canonical fields.subject_sample_labels 与其实际 sample_ids、各数值的事实主体及原文，不能只看 primary sample_label；某事件出现在样品卡上，不证明条目提到的所有数值都属于该样品。每个新 item.fields 必须显式用 subject_sample_labels 字符串数组表达唯一权威归属，真正共同事实可含多个主体，无明确主体为 []。sample_label/related_sample_labels 仅为旧接口兼容，不能替代 canonical；mentioned_sample_labels 只是提及，不构成专属测量或状态归属。对旧记录仍结合真实来源核对，不用缺失 canonical 的理由推造主体。共同备注不应携带某个样品独有的数值，应引用其原事件；数值分属不同主体时需各自记录。发现结构化链接与原文主体冲突时，可以依据原文回答并明确具体冲突、事件和来源，但不能宣称持久化归属已经修好，也不能在只读任务中重建事件掩盖问题。

当前计划/待测清单优先消费 current_state 及每条记录的 lifecycle_state，按具体主体区分 pending、in_progress、completed、cancelled、superseded、unknown。原 fields.state/status、旧排队原文和原始计划是历史依据，不能覆盖显式 state_updates 投影出的当前状态；completed/superseded 的项目不要再列为当前待办。state_updates 内的 subject_sample_labels 仅是此次变化的主体，必须属于承载该更新条目的 fields.subject_sample_labels，不能借此把提及对象也视为完成。共享计划可能仅部分主体完成，不能按整条事件给所有样品统一状态。legacy记录没有显式状态时保持 unknown，并查来源说明可证实的事实与缺口，不凭事件名、日期或已存在某个测量自行推定已完成；只读答复不能冒充已落盘状态更新。需要补齐持久状态时，将真实目标事件ID、版本和证据交给具备写权限的角色。

复核完成/取代状态时，枚举该样品全部 current_state 为 pending / in_progress 的目标，逐条对照来源与完成事实，不能只检查已更新的第一个 unknown。仍为 pending 的同项旧排队/待测条目，即使正文已经说完成，也要交付其真实ID、版本和依据，由主 Agent 让有权限的 capture 补齐 superseded 并读回；只读复核不能冒充已修好。其他未知及无证据已完成的计划继续保留。

样品/事件检索为空时，若任务或历史提供页面，直接读取 evidence.page.read 中的转写；也可按已知 proposal_id 读取已有记录。原始记录足以支持的问答可以直接综合为带 page_id/block_id 的答案，准确说明当前保存/采纳状态，不需要先批准事实或反复调用只接受事件的构建器。上述回答构建/渲染工具是可选辅助，不能让它们阻塞已经有原始依据的问题。按样品归组并使用有来源的 occurred_at 或原文日期；不知道日期或样品关联时具体指出，不能把整理时间当实验时间，也不能把字段缺失等同于整条记录不可用。
