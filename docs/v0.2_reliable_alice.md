# v0.2 Reliable Alice

## Release goal

v0.2 turns the Phase 1A inventory demo into a policy-governed event execution core.

```text
gateway message
  -> idempotency check
  -> rule/agent parser proposal
  -> executable schema validation
  -> deterministic policy
       -> approve
       -> pending confirmation
       -> reject
  -> immutable event + audit persistence
  -> guarded transaction
  -> inventory projection update
```

## Invariants

1. Every operational write is linked to one persisted event proposal.
2. Every event proposal has an audit decision.
3. One event can create at most one inventory transaction.
4. A gateway message identity is processed at most once per source.
5. Confirmation creates a new event revision; it does not erase the original proposal.
6. Explicit confirmation cannot bypass hard constraints such as negative inventory.
7. Gateway and LLM implementations do not own policy or database writes.

## Event lifecycle

- `proposed`
- `pending_confirmation`
- `approved`
- `rejected`
- `applied`
- `superseded`

An approved event is immediately moved to `applied` when execution is enabled. `approved`
is retained for dry-run and delayed-execution workflows.

## Gateway contract

Gateways should call the core with:

- `source`: stable adapter name such as `qq`, `webchat`, or `openclaw`
- `source_message_id`: stable message identifier from that channel
- `raw_text`: original user-visible message

The same `(source, source_message_id)` returns the previously persisted result instead of
applying the action again.

## Confirmation contract

Pending events can be:

- rejected;
- explicitly confirmed when the warning is soft;
- corrected and confirmed with an item, amount, unit, action, user, or project.

Hard policy violations remain rejected after confirmation.

## CLI examples

```bash
chemclaw ingest-message "Added 100 g KBr" \
  --source webchat \
  --source-message-id message-001

chemclaw list-events --status pending_confirmation

chemclaw confirm-event EVENT_ID --confirmed-by user_001

chemclaw confirm-event EVENT_ID --unit g --amount 5

chemclaw confirm-event EVENT_ID --reject
```

## Current boundary

v0.2 is still an inventory vertical slice. It does not yet implement:

- a production chat gateway;
- Excel import/projection;
- experiment-memory execution;
- planning and booking execution;
- an LLM parser.

Those components should integrate through the event and policy contracts above.
