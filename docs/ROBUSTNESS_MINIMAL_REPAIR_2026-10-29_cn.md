# ChemClaw 最小鲁棒性修复交付（2026-10-29）

五项修复已实现并部署到本地主服务。应用仍由LLM判断任务、化学语义、主体归属和拆分规模；本地新增逻辑限于预算、真实回执、来源/版本索引与显式续作控制。旧英文测试95.7分、六图整理6partial及原审计29/30均保留，没有补库、补跑或重评分。

| 问题 | 已实施的最小修复 |
| --- | --- |
| 委派偏晚、无收尾余量 | 每次模型请求/工具视图附当前共享预算。900秒新任务默认预留120秒收尾，工作期结束停止新模型推理、写入和委派；已发出的Core请求保留到回执或原硬期限。硬期限、工作期限及工具余额写入CP，恢复不重开窗口；旧检查点保持原hard-only策略。管理员可配置收尾预留，短于60秒任务默认不新增预留。 |
| 首批落盘偏晚 | 精简capture/orchestrator重复指令，要求LLM先完成有来源的小批create→读回→记录进度，再扩大范围；保留主体、单位/条件、版本、人工纠错、计划/实做等约束。这是执行契约与预算提示，尚未证明真实GLM必然在某秒前完成首批。 |
| 超时掩盖已完成成果 | 复用knowledge_delivery生成确定性执行摘要，列真实写入、读回、对象ID和缺口。它不重建科学答案、不自动将partial改为completed，也不把页面/块有关联当作语义完整。 |
| 继续缺少安全入口 | 界面新增“继续整理未完成项”，显式POST原job的continue路由；同一原job仅创建一个幂等续作子job，进一步继续沿子job成链。新任务保留原会话与权限，重读当前页/事件/版本，复用原OCR，不修改或重放旧任务。版本变化失效旧块游标；未知效果、已取消且缺完整journal、裁剪检查点回执均先要求核查。 |
| 主服务健康缺少基线 | 新增免费loopback健康快照与前后比较工具，独占记录起止时间、状态和可选进程身份；缺失、迟采或跨越测试起点的前测不会伪装成有效基线。禁代理、重定向、凭证、查询参数及模型探测，不读正文，不自动启动服务。 |

进度投影capture_progress保存来源版本、引用块、已保存/读回事件及优先待核查块，knowledge_complete始终为null。它默认不超过32KiB，超限会标truncated、total_counts/omitted_counts，并降低来源清单完整性标记；完整工具journal/checkpoint仍保留。省略不代表已处理，已引用的块也可能仍有未整理事实。无法完整定位原目标来源时拒绝静默缩小范围。
