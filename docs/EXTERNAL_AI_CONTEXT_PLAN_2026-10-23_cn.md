# 面向外部 AI 的研究上下文接口：现状与优化规划

日期：2026-10-23。范围：只读代码审查、隔离验证与接口规划。本轮未修改产品代码、主库、运行配置或人的界面；未调用研究模型。两个开发 Agent 分别审查数据聚合与外部协议/授权。

## 结论

现有 ChemClaw 已有 HTTP 能力入口和 MCP 单入口，可以作为外部 AI 的研究记忆服务基础。当前短板在样品上下文聚合、契约一致性、读取新鲜度和完整性表达。

建议让外部强 AI 负责研究目标、工具选择与推理，ChemClaw 提供权限内的知识、原件、版本和明确缺口。按已保存关联读取样品上下文不调用内部模型；需要从原文发现隐含关联、消解歧义或补整理时，由显式的 LLM 任务处理。普通读取不能暗中触发整理或写回。

## 1. 现有能力及边界

| 部分 | 当前实现 | 与目标的距离 |
|---|---|---|
| HTTP | `GET /v2/capabilities`；`POST /v2/capabilities/{id}/invoke`，JSON envelope | 可直接供程序调用，普通读取目前也要求操作ID并进入回执缓存 |
| MCP | `POST /v2/mcp`，有 initialize、tools/list、tools/call，复用 Core | 已有单入口，缺少统一的样品上下文工具；只验证了现有适配，未验证具体外部产品接入 |
| 样品卡 | `query.samples.list` 返回项目样品、展开记录、来源、未知和质疑/来源过时状态 | 是全项目展开视图，schema中的limit未用于handler，无按单样品聚合、游标和历史快照契约 |
| 时间线 | `query.sample.timeline` 已支持共同事件、发生时间、来源、纠错依据和事件as-of读取 | 缺少一并返回的引用原文、完整修订链、相关外部产物和聚合完整性说明 |
| 来源/事件 | `memory.event.read`、`memory.proposal.read`、`evidence.page.read/original` | 对外可调用，但外部AI需要自行拼接；page.read读取当前转写，缺少按引用版本/块的直接读取契约 |
| 搜索 | `query.events.search` 结构化候选加全文候选 | 候选搜索不保证全量；全文分支与结构化分支并集，不能视为严格的样品关联集合 |
| 旧答案生成 | `query.answer.build/render` 的确定性builder | 固定提取amount、measurement_value、标量temperature等字段，不覆盖任意嵌套LLM字段；不适合作为外部强AI取得完整上下文的主入口 |
| Python只读客户端 | 仅开放search、timeline、answer.render、report.read四项 | 缺少samples.list、event.read、page.read及新的聚合能力 |
| 外部产物 | external_results已有计算/文献/外部实验来源、工具/方法/附件记录 | 未建立统一的、可直接按sample_id查询的类型化关联；不能自动将整个项目外部产物归给一个样品 |
| 权限 | 凭据映射human/agent/service身份，再按项目viewer/member/owner授权 | 基础可复用；客户端白名单不是服务端权限边界；当前按项目授权，不是按样品授权 |

主要代码依据：

- `src/chemclaw_lab/api.py`：HTTP/MCP路由与身份认证。
- `src/chemclaw_lab/clients.py`：只读白名单、客户端操作ID。
- `src/chemclaw_lab/mcp.py`：MCP发现、调用与输出。
- `src/chemclaw_lab/capabilities.py`：角色、查询handler、读取回执缓存与重放授权。
- `src/chemclaw_lab/sample_cards.py`、`query.py`：样品关联、版本和查询投影。
- `src/chemclaw_lab/answers.py`：旧固定字段答案builder。
- `src/chemclaw_lab/agent_gateway.py`：当前工具schema及Pi专用精简原文视图。

内部 run-token 工具网关用于受托任务的manifest、预算和fencing。外部AI单纯读取研究记忆宜使用专门的service身份与项目viewer权限，无需先启动一次内部Agent运行。

## 2. 已复现的优先问题

### P0：读缓存、操作ID与撤权重放

`ReadOnlyQueryClient` 每个新实例从 `ext-search-1` 开始计数；Core对普通读也保存 `operation_results`。隔离HTTP验证得到：

1. 首次搜索返回0条；添加新事件后，重连新客户端仍返回旧0条；原客户端下一次新ID搜索返回1条。
2. 新客户端首次换查询参数，触发409 `idempotency_conflict`。
3. 同一service先有P1/P2 viewer，缓存全可见范围搜索与P1事件读取；撤P1、留P2后，旧ID仍可重放P1内容。新ID搜索只见P2，新ID直接读P1则被拒绝。

根因：`invoke_capability` 对读取使用永久回执缓存；`_authorize_replay` 仅检查envelope外层project_id/scope，部分读的真实范围在result.scope或对象内部，外层不足以重新授权。

优化约定：普通读取重新执行并检查当前权限；固定历史读取使用显式snapshot。request_id用于追踪，写入operation_id用于幂等，snapshot用于版本固定，三者分开。任何缓存/历史结果都需重新校验当前源对象权限。旧读缓存绕开或失效处理，保留写入的幂等与fencing。客户端ID不能在重连时碰撞。

### P1：工具schema与执行不一致

- MCP从Pi的参数schema表借用定义，缺失项退回宽松任意对象。
- `query.answer.render` 工具定义要求answer，真实执行要求question。
- `memory.event.read` 定义声明knowledge_as_of，实际handler忽略该参数；真实include_history能力未被定义描述。
- `evidence.page.read` 的agent精简视图在Pi网关转换，对外HTTP/MCP直接调用没有自动复用该转换。

应将面向调用者的输入/输出契约集中定义，HTTP、MCP和Pi引用同一份；必要的传输视图转换单独处理。已发布但未实现的参数不能静默忽略，应实施或明确拒绝。先完善读取面，无须重写全部能力框架。

### P1：聚合与覆盖范围缺口

当前多个接口的数据形态各有用途，但无法一次说明“这个样品在指定快照下有哪些已知记录，以及还缺什么”。多次请求还可能在人工纠错期间读到不同版本。source_stale、unknown、disputed等状态分散，外部AI容易只拿到时间线片段。

小材料只读观察：2样品全项目卡片JSON约17,980 UTF-8字节，单LC-A时间线约7,537字节；这仅说明返回结构和重复开销，不是规模化性能测试。`search(sample_label='LC-A',text='LC-B',limit=1)`返回2个候选，分别来自事件与全文分支。当前没有总量/游标/预算截断契约，不能把返回数量当作完整数量。

## 3. 核心新增能力：query.sample.context

复用现有HTTP/MCP入口，新增一个Core能力。外部AI已知道样品ID时，一次取得该样品权限内、已明确关联的当前上下文。提供项目+标签时，可在同次调用精确解析；同名/别名歧义返回候选，不擅自合并。

示意请求（拟议，不是已实现接口）：

```json
{
  "project_id": "proj_lab",
  "sample_id": "smp_...",
  "include": ["events", "cited_blocks", "provenance", "revision_index", "relations"],
  "snapshot": {"mode": "current"},
  "budget": {"max_bytes": 64000}
}
```

请求可另选明确历史snapshot/as-of，以及后续游标；具体枚举在实施时冻结。字节预算可直接验证，token数只能按选定tokenizer测量或明确标为估计。传输接口不会把max_bytes解释为按化学重要性删字段。

响应需包含：

| 字段 | 用途与约定 |
|---|---|
| schema_version | 独立的上下文契约版本，支持外部客户端稳定消费 |
| sample / resolution | ID、标签、别名、项目，以及唯一/歧义/未找到状态 |
| snapshot | 读取基准、生成时间、对象版本清单或指纹；后续分页固定同一版本集合 |
| events | 事件ID、revision、kind、发生时间、完整可扩展fields、原文片段及全部明确样品链接；共享事实同一ID，不按样品复制 |
| evidence | 精确引用的page/transcript_revision/block及文本；历史引用能读到历史块，当前转写变化另行标记；原始图片/大型文件按需读取 |
| revision_index | 纠错与作废的版本关系、当前有效版本、修订依据；默认当前事实，完整历史可展开 |
| relations | 已保存且有来源的明确关联，注明关联依据；推断关联单独标记并附LLM来源 |
| source_context | 与样品记录有关的页面说明、模拟来源等；共享页其他样品的文字保留为来源上下文，不自动成为本样品事实 |
| quality / issues | 已存未知、质疑、来源过时、缺失引用、未解决样品归属等；保留具体对象与原因 |
| coverage | 已找到/已返回的授权对象数、实际包含的部分、遗漏原因、下一页游标；区分检索返回完整和知识整理完整 |

未知数值保留null与原有原因；原文没写不能被本地升级为“确定未做/不存在”。没有保存预期字段时，可说明“未找到该字段”，不能声称原件一定未记录。

“所有相关信息”分为两个范围：

- **明确关联范围**：已存样品链接、共同事件、证据块、修订和类型化外部产物关联。Core负责稳定取全，版本与权限可检查。
- **潜在语义关联范围**：原件中的隐含指代、跨页继承、未归属记录等。提供候选与已知缺口；需要时启动显式LLM整理/检索任务。不得把候选默认为样品事实，也不能宣称覆盖尚未阅读的资料。

第一页的“完整”只能指已请求部分的授权对象已取全。若因预算分页，应返回partial/next_cursor，而不是悄悄截断。知识是否整理完整由实际处理回执和LLM判断共同说明，不能按“每块已有一事件”宣称语义全覆盖。

## 4. 配套能力与实现边界

最小对外工具集：

1. 扩展现有样品发现能力：紧凑目录、项目/ID/标签/别名查询、稳定分页、明确歧义。
2. `query.sample.context`：单样品主交付物，必要时再扩多样品批量获取。
3. 完善来源读取：按page+transcript revision+block IDs读原文，按event ID+revision读事件；可批量展开，保持当前权限检查。

MCP工具输出提供清晰的结构化对象与输出schema，保留需要的文本兼容；工具名和HTTP能力保持同源映射。原件默认返回引用和元数据，避免将base64大文件塞进上下文；需要图像时通过授权读取获取。外部序列化去除本机storage_path等调用者不可用的实现细节。

数据层优先复用SQLite与现有events/transcripts，不先增加向量库或图数据库。新增轻量查询投影/索引可以服务sample_ids关联，所有投影保留原始对象ID与revision。普通按ID读取零内部模型调用；LLM主导语义建档、关系判断、研究规划与候选扩展。

一次上下文聚合应在一致读事务中取得对象集合与版本；分页/后续读取使用显式版本清单固定视图，不能只返回字符串current后重新查最新数据。历史样品身份、转写及外部结果若尚不支持同一历史口径，应明确声明支持范围，不把局部事件as-of描述成全系统快照。

外部计算/分析写回放到独立后续能力，显式绑定sample_id、输入snapshot/事件版本和方法工具。其结果保持computed/external语义，不能冒充实测，也不自动执行库存或预约。

## 5. 建议实施顺序

| 顺序 | 交付物 | 验收重点 |
|---|---|---|
| P0 读取基础 | 新鲜读取、撤权后重新授权、客户端唯一请求ID；读取schema纠偏 | 重连不返回过期current；撤P1留P2时旧ID/缓存/历史读取均不能返回P1；写入幂等与取消fencing不退化 |
| P1 最小样品上下文 | context能力、精确引用读取、紧凑发现；HTTP/MCP同源 | 已知ID、小材料一次取全所请求内容；唯一标签也可一次解析取回；样品歧义如实返回；常规读取零LLM调用 |
| P2 大资料与扩展 | 固定快照游标、字节预算、按版本增量、批量样品、明确外部产物关联；可选LLM候选扩展 | 不丢阶段/条件/未知/修订；跨页并发纠错后分页不混版本；遗漏可继续取；候选不冒充事实 |
| 接入验收 | 独立外部客户端/MCP客户端示例和少量强AI工具调用 | 外部AI不看网页/聊天摘要即可回答样品经历、修订及未知；引用可打开；工具参数由schema可正确构造 |

P0与P1可以作为第一轮开发范围，人的界面保持现状。远程云端AI无法直接读取用户机器的127.0.0.1；先验证本机外部客户端，再按首个实际接入对象决定本地桥接或受控远程部署。此步骤不要求现在开放网络端口或共享人的凭据。

## 6. 验收用例与测量

- 已知ID、唯一别名、同项目重名、跨项目同名和未知样品。
- 共同操作/计划、独立数值、跨页追加、返工、计划未执行、未知/null、模拟来源。
- 当前纠错值与原页旧值并存；来源转写更新后保留原引用并报告过时；同一读快照不混版本。
- 数据超过预算时partial+游标，继续读取后恰好覆盖请求的授权对象集合；不透露无权限对象计数。
- 默认读取不修改业务知识，不创建样品、提案或实验事件，不调用内部LLM；日志/快照等服务元数据单独计量。
- 新鲜度与撤权重放回归；JSON schema样例与真实handler端到端一致。
- 测量调用次数、返回字节、处理耗时、被省略对象、内部模型调用数及引用可解析率。小材料已知ID以一次context调用为目标，耗时阈值须在实施后冻结数据规模再设定；本轮不虚构性能保证。

本轮现有外部HTTP客户端/网页机器一致性两项、MCP初始化/能力复用两项测试通过。这些测试范围小，未覆盖本轮新复现的缓存撤权缺陷，也不证明具体第三方AI产品已接通。当前结果是规划依据，不是新接口实现完成报告。
