# v0.3 Messaging + Excel

Version 0.3 exposes the Reliable Alice core through a gateway-safe HTTP boundary and
adds an auditable Excel migration/projection workflow.

## Release boundary

The release provides:

- a local, zero-runtime-dependency HTTP server;
- API-key protection whenever the server binds beyond loopback;
- external gateway identity mapping to ChemClaw users;
- explicit `user_id` and `project_id` attribution;
- atomic and idempotent Excel imports;
- generated Excel projections from SQLite;
- a small standard-library client for gateway adapters.

It does not claim production WeChat or QQ integration. Those platforms remain thin
adapters over the stable HTTP contract.

## Run the API

Local-only development:

```bash
chemclaw serve-api --db chemclaw_lab.db
```

Remote binding requires an API key supplied through an environment variable:

```bash
export CHEMCLAW_API_KEY="replace-with-a-secret"
chemclaw serve-api --host 0.0.0.0 --api-key-env CHEMCLAW_API_KEY
```

On PowerShell:

```powershell
$env:CHEMCLAW_API_KEY = "replace-with-a-secret"
chemclaw serve-api --host 0.0.0.0 --api-key-env CHEMCLAW_API_KEY
```

The key can be sent as `Authorization: Bearer ...` or `X-API-Key: ...`.
`GET /health` is intentionally unauthenticated.

## HTTP routes

| Method | Route | Purpose |
| --- | --- | --- |
| `GET` | `/health` | Version and SQLite integrity |
| `POST` | `/v1/identities` | Map an external gateway user |
| `GET` | `/v1/identities` | List mappings |
| `POST` | `/v1/inventory/messages` | Ingest an inventory message |
| `POST` | `/v1/inventory/events/{event_id}/confirm` | Approve, correct, or reject |
| `GET` | `/v1/inventory/events` | Query event proposals |
| `GET` | `/v1/inventory/chemicals` | Query current inventory |
| `GET` | `/v1/inventory/export.xlsx` | Download a generated projection |

Every message request must carry a stable `source` and `source_message_id`. A retry
must reuse the same ID so the core can return the original result without applying a
second inventory change.

## Identity mapping

Create a mapping before accepting messages from an external account:

```bash
chemclaw map-identity openclaw CHANNEL_USER_ID user_001
```

Gateway messages can then send `external_user_id`. The API resolves it to a known
ChemClaw user and rejects unmapped or conflicting identities. `project_id` is also
validated when supplied.

## Excel workflow

SQLite is always the source of truth.

Generate a disposable workbook:

```bash
chemclaw export-excel inventory.xlsx
```

The workbook contains:

- `Inventory`: current inventory, thresholds, and formula-driven low-stock flags;
- `Transactions`: immutable stock-changing records;
- `Events`: proposal and confirmation lifecycle;
- `README`: provenance and editing rules.

Import an initial workbook:

```bash
chemclaw import-excel inventory.xlsx --mode create --imported-by user_001
```

Merge reviewed changes later:

```bash
chemclaw import-excel inventory.xlsx --mode merge --imported-by user_001
```

Imports validate the complete workbook before writing, run inside one immediate
transaction, and use the file SHA-256 hash for replay protection. Initial amounts
become confirmed `opening_balance` events. Changed amounts become confirmed
`adjust` events. Compatible unit changes are converted into the stored unit for
amounts, thresholds, and automatic-change limits. Duplicate chemical identities or
names are rejected. Any rejected row rolls back the whole batch.

## Safety invariants

1. Gateways never write SQLite directly.
2. Amount changes always persist an event before state mutation.
3. Policy, audit, and inventory transaction records remain linked.
4. External identities must resolve to a lab user.
5. Remote HTTP binding cannot start without authentication.
6. Excel is an explicit import/export boundary, not live operational memory.
