## 已实现的改动

1. **截断后有界续做**：将原任务续做与只读完成协议修复分开。确认输出因长度截断后，每个 Agent 运行默认至多续做一次，整棵任务树沿用原绝对截止时间和共享工具余额；先成功读回来源或已有对象，再允许原权限内写入或委派。截断参数不执行。相同完整参数的成功写入复用原回执，同 ID 改参拒绝，未知写入结果停止待核查。
2. **独立发现来源页**：复用 `evidence.pages.list`，补充分页和客观来源状态，并向三个研究角色开放。独立 reader 从四个只读工具扩展到五个，能发现尚未形成样品知识的页面。原件已登记、OCR 成功、事件链接数量均不表示知识完整，`knowledge_complete` 保持未知。
3. **模型请求观察**：分别记录 Pi 与 OCR 的请求意图、实际 HTTP 尝试、SDK 重试、耗时、错误类别以及供应商实际返回的 token 用量。按请求 ID 去重，`not_sent` 不计实际请求。没有返回的用量或费用保留 `null`，不使用 SDK 配置的零价格推断免费。安全账本不记录正文、图像、密钥或隐藏推理。
4. **额度与阶段保护**：明确区分余额不足 `1113` 和一般限流。任务树收到额度错误即停止后续请求；新评测 runner 保存项目、会话、已提交任务、页面和下一步游标，暂停后续上传/OCR。人工确认恢复资源后只放行尚未提交的新步骤，不复活旧终态任务。外部 reader 屏障持久保存，不再把一小时人工等待误判为整轮失败。

没有新增历史上下文压缩模块：检查发现来源正文原本在每轮临时构建，历史消息主要保存页 ID。没有证据支持再加压缩层，也不宣称本轮已节省上下文 token。
