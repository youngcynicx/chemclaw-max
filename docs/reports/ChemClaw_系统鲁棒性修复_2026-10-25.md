# ChemClaw 系统鲁棒性修复（2026-10-25）

本轮只修运行与持久化链路。保持 LLM 决策、多 Agent 委派及现有权限/写入契约；模型、提示、研究任务、语义规则和模型预算不变。不重传六图、不调用真实模型补测，不改原 55.5/100 评分。

## 已修问题

1. **检查点重复数据导致确定性超限。** 原运行会同时保存 messages、tool_calls、delegations 及包含同批回执的 result。保留原 1,800,000 字节存储上限，新增按完全相同 JSON 子树/字符串去重的可逆引用编码。小检查点沿用旧格式，大检查点不删正文、字段、回执或状态。先脱敏，再编码；真实内容仍可由 Core 的持久化校验直接检查，没有用压缩/二进制绕过检查。解码按运行 ID、引用顺序、位置、深度、节点数与展开体积校验，恢复为独立对象，不共享可变别名。
2. **合并恢复请求超过本地 2 MB 上限。** Python→本地 Node 的大请求采用 gzip；2,000,000 字节线上限制保留，解压和恢复数据的总展开量限定 8 MiB。它是本地传输/存储边界，不是模型上下文或 token 预算。HTTP 按 Buffer 收齐后统一 UTF-8 解码，避免中文字符跨网络分块损坏。
3. **确定性错误被误判为临时故障，反复恢复同一任务。** 检查点超限/损坏使用不可重试错误；运行请求超限同样明确终结。整棵任务树停止，聚合各运行的真实回执，输出最多 64 KiB 的终态摘要。已有成功回执保留 partial 与对象引用；其余按实际证据 failed，不伪造 completed。摘要被 Core 明确拒绝时，使用固定小体与权威运行/检查点定位终结。继续使用正常租约与 claim_epoch 校验，取消和旧 worker 无法越权收尾。
4. **损坏恢复数据可能降格为普通工具错误。** 显式 null/标量/数组、损坏引用、错运行 ID 的检查点拒绝恢复；动态子任务恢复错误也触发整树停止，不能再由父模型声明 completed。临时网络、服务或检查点存储故障仍可恢复；不把不确定写入当成失败后自动重做。

完整回执保留在 Core 的 operation results 与 durable checkpoints；终态控制摘要不再次复制巨量正文。编码/传输超过可恢复边界时明确停止，不无限提高预算或丢弃研究数据。
