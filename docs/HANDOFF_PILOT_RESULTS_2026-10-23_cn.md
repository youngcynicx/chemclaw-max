# ChemClaw 外部 AI 交接与最小对照：首轮实测

日期：2026-10-23。运行目录：`D:\Chem\ChemClaw-Lab-S10-Repair\work\publication-handoff-2026-10-23`。

## 本轮结论

已交付可复用的外部 AI 运行器，并完成双样品、三阶段模拟记录的三条件真实模型运行。普通聊天、单 Agent、多 Agent 的答案质量接近；本轮最明确的系统收益是知识持久化、来源追溯、修订及独立 AI 接续。这一先导实验尚未测出多 Agent 的整体优势，下一轮优化应集中在归属与状态维护质量。

人的界面与业务主库沿用现状。本轮新增资料、身份及模型写入均在隔离案例库；常用主服务没有重启。业务代码仅修复显式共同样品标签的形状兼容，新增代码主要用于运行与评测。

## 1. 贯穿案例与运行方法

输入是明确标注 **SIMULATED / text-only synthetic** 的三页碳材料记录，不是湿实验结果，不含 OCR。输入、六项任务和评分点在本轮结果审阅前冻结，哈希见 `evaluation/input-freeze.json`。

| 阶段 | 到达的记录 | 核心任务 |
|---|---|---|
| initial | CCX-A/B 共享 70℃×45min → 105℃×90min；质量36/31mg；计划CO2测试 | 重建经历；交接计划与未知 |
| append | A测得2.40mmol/g，20℃、1.00bar；B排队未测 | 样品比较；完成/待执行状态 |
| correction | A原质量36→38mg的录入纠错；B补测2.10mmol/g | 当前事实、历史依据及JSON交接 |

三个条件均使用现有 `glm-5.3-flash` 配置、同一材料与问题，每条件每阶段一次，未筛选最佳回答。

- **direct**：每阶段读取截至该阶段的全部原文，直接回答，无知识工具。
- **single**：同一 Pi/Core，单一 Agent 使用三个角色可达工具并集，公共＋capture 工作提示，禁止委派。
- **multi**：产品 orchestrator/capture/query 三角色，模型自主委派；三个阶段都真实委派了 capture。

single/multi 根任务上限均为300秒、60工具预算，单次输出上限16384；角色提示、工具路由及子角色时限不同，实际总模型开销没有强制相等。数值纠错由宿主依据第三页执行人工纠错接口，两条件执行同样操作，保留模型原有质量字段名；没有给单体增加人的审批能力。

## 2. 最小对照结果

| 条件 | 完成阶段 | 答案核对 /24 | 持久状态核对 /10 | 三阶段总时间 | 记录工具调用 | 委派 |
|---|---:|---:|---:|---:|---:|---:|
| 普通聊天 direct | 3/3 | 23.5 | 不适用 | 45.66秒 | 0 | 0 |
| 单 Agent single | 3/3 | 23 | 9 | 201.66秒 | 14 | 0 |
| 多 Agent multi | 3/3 | 23.5 | 7.5 | 259.36秒 | 24 | 3 |

答案和状态分别评价：direct 没有数据库不扣答案分。single/multi 最终均有2样品、3提案、11个事件、12行事件版本，A质量在同一事件上修订到revision 2；未生成库存交易或人工采纳签字。

这里的分数是**开发 Agent 按冻结核对点进行的定性检查**，不是人类受试者评价、盲评或统计推断。第二审阅保存在 `evaluation/independent-assessment.json`；root统一复核将multi的C7从1调为0.5，因为材料未给出重复次数，回答仍写“各有一次”，与single采用相同事实标准。原始评分和复核都保留于 `evaluation/adjudication.json`。

Pi首轮公开回执未提供完整供应商模型请求/token，因此这些成本留空；表中工具调用按实际回执ID去重，不含宿主归档和人工纠错。阶段时间与计数见 `evaluation/measured-stages.csv`。三条件没有在同一指标上同时降低成本并提高质量，后续应通过更长记录和留出任务检验多Agent分工的收益。

## 3. 外部 AI 接续

独立 Codex 子Agent采用无父会话历史的初始任务，只收到研究目标及四个工具，之后在同一Agent中接收项目更新任务。原件必须经接口取得；未提供源码、数据库、参考答案或开发交接。四工具为：目录、样品上下文、事件版本、精确原文。

初始交接已完成：5项工具请求中4项成功，1项expanded目录请求被运行器拒绝；它自行改用catalog，读取两样品context并追查原页，回答核对8/8。它发现样品context中的共享操作和计划归属不足，准确用原文补充，未伪造共享事件ID。

更新后独立交接也已完成，文件为 `external-codex/correction/final.md`、`handoff.json` 和 `summary.json`。本轮10项请求中8项成功，正确识别A当前质量38mg及36→38的revision 1→2纠错、A/B分别2.40/2.10mmol/g、两项计划已完成；JSON的重复次数/误差等未知用null附原因，没有把未知重复次数写成n=1。root按同一核对点评为8/8，两轮四任务合计16/16，与三阶段24点对照分开报告。只读核查确认嵌入/独立JSON相同，9对事件/版本和15个原文块引用全部可解析。

首次连接的两条失败因准备服务进程被回收而发生，已保留；恢复同端口同身份、同一最终状态后继续，未删除失败或重选答案。手动Codex耗时包含准备、调度和恢复等待，不能与自动API推理耗时直接比较；其模型调用/token无法由本地运行器测量，记录null。

自动Chat API路径另外完成了一次真实GLM工具循环，首次即成功：4个模型请求、4个工具/Core请求，34.84秒，输入19286／输出1062／合计20348 token。模型自主选择目录→A context→B context→原页；读取没有启动ChemClaw内部模型。该组初始回答核对8/8，作为运行器联网验证，与独立强AI及三条件结果分开报告。

人工工作台所用sample-card投影与外部context进行了HTTP字段核对：多Agent初始2次事件出现、最终9次事件出现，单Agent最终18次事件出现均一致，包含事件ID/版本、字段、原文、未知项与来源引用。共同事件在两个样品出现两次，因此该数不能当作唯一事件数。该检查验证两端消费相同记录，不代表人类任务耗时研究。

## 4. 首轮暴露的问题及已完成修复

**已修：共同样品标签的顶层结构兼容。** 多Agent真实输出在item顶层给出`related_sample_labels`，原兼容层只搬移单个`sample_label`。共享操作、计划和未知项因此被保存为未归属记录。现把两个显式标签数组沿用同一形状归一化机制搬入fields，nested同名值优先；关联仍由LLM明确指定。

同一份成功模型输出的6个原items、同一份6个原始blocks精确离线重放，未增加模型调用：

| 指标 | 修前 | 修后 |
|---|---:|---:|
| 样品 / 事件 | 2 / 6 | 2 / 6 |
| 共享事件 | 0 | 3 |
| 未归属记录 | 3 | 0 |
| 每样品context事件数 | 1 | 4 |

这是产品回归，未覆盖原首轮数据库或上表分数。证据和修前源码哈希见 `product-fix/exact-replay-results.json`。为了让首轮后续阶段保持相同产品行为，恢复评测服务时仅在隔离进程内加载了冻结旧归一化函数。

**下一轮直接优化两项：**

1. 把“对比/备注涉及另一样品”和“数值属于另一样品”区分清楚。single的B补测事件关联A+B，multi的共同未知说明又携带A的2.40数值，结构化消费者仍需结合文字判断。优先改LLM整理和读回验收要求，保持通用数据字段。
2. 让LLM明确写出计划完成/取代关系和当前状态。旧`not_executed`、`queued_not_tested`与后续完成记录并存时，外部AI能据日期解释，但需要额外推理。保留历史，同时提供清晰的当前状态及其依据。

这两项比扩展检索基础设施更直接影响交接。修后先复跑当前案例验证回归，再增加一个输入更自然、需要跨页关联的留出案例；同时开始收集真实研究员的纵向记录与查找/交接用时。
